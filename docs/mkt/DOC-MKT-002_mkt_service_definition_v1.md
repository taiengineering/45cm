## 1. MKT 서비스 정의

MKT는 TAI를 아직 모르는 고객이 자신의 문제를 해결하는 과정에서 TAI를 발견하고 첫 관계를 시작하도록 만드는 마케팅 서비스이다.

MKT는 광고나 영업이 아니다. MKT는 고객의 문제를 해결하는 정보를 제공하고, 그 과정에서 TAI의 법령진단을 자연스럽게 경험하게 하는 구조이다.

---

## 2. MKT 서비스 목적

TAI를 찾지 않아도 TAI를 만나게 한다. (GOAL-MKT-001)

고객은 TAI를 검색하지 않는다. 고객은 법령을 찾고, 의무를 찾고, 점검방법을 찾고, 처벌기준을 찾는다. MKT는 이 과정에서 TAI를 발견할 수 있는 구조를 만든다.

---

## 3. MKT 서비스 구성

### ① 법령검색 페이지

법령엔진 데이터를 기반으로 법령, 조문, 의무를 검색할 수 있는 웹 페이지를 제공한다. 검색엔진에서 법령/의무/점검/처벌을 검색할 때 TAI 페이지가 노출된다.

### ② 무료진단 셀프서비스

방문자가 KSIC/시설/설비/공정/작업을 입력하면 즉시 Applicable Obligation 결과를 확인할 수 있다. 회원가입 없이 시작할 수 있다. 전체 결과는 이메일 등록 후 제공된다.

### ③ SEO 콘텐츠 자동화

고객이 반복적으로 검색하는 10가지 수요군에 대응하는 페이지를 법령엔진 데이터 기반으로 생성한다. 법령 개정 시 자동 업데이트된다.

---

## 4. MKT 서비스 구조

```
검색엔진/AI 검색
    ↓
법령검색 페이지 ← 법령엔진 데이터
    ↓
무료진단 셀프서비스 ← 법령엔진 API
    ↓
결과 미리보기
    ↓
이메일 등록 / 회원가입
    ↓
전체 결과 (Excel / SaaS 연결)
    ↓
PQL 판정 → 후속 접촉 자동화
```

---

## 5. MKT 서비스 핵심 원리

### 수단은 Goal이 아니다

무료진단은 Goal이 아니다. 법령검색도 Goal이 아니다. AI 검색도 Goal이 아니다. 이들은 모두 고객과 첫 관계를 시작하기 위한 수단이다. 수단은 언제든 변경될 수 있지만 Goal은 변경되지 않는다. (GOAL-MKT-001 Principle)

### 발견 → 경험 → 전환 → 신뢰

MKT 서비스는 4단계 구조를 따른다: 고객이 TAI를 발견하고(P1), 즉시 경험하고(P2), 유료로 전환하고(P3), 결과를 신뢰한다(P4). 이 모든 것은 1인이 운영 가능한 자동화 구조로 동작해야 한다(P5).

### 법령엔진이 MKT의 데이터 소스

MKT의 모든 콘텐츠와 진단 결과는 법령엔진의 데이터에서 나온다. MKT는 별도의 콘텐츠를 만들지 않는다. 법령엔진의 정확한 데이터가 MKT의 신뢰를 만든다.

---

## 6. MKT 서비스 측정

### 발견 (P1)

검색 노출 수, 페이지 유입 수, 검색엔진 색인 페이지 수.

### 경험 (P2)

진단 시작 수, 진단 완료 수, 결과 열람 수.

### 전환 (P3)

이메일 등록 수, PQL 수, 상담 전환 수, 유료 전환 수.

### 신뢰 (P4)

재방문율, 결과 공유 수, Excel 다운로드 수, 상담 후 계약율.

---

## 7. MKT와 TAI 관계

MKT는 TAI 법령 운영 플랫폼의 마케팅 영역이다. MKT는 독립적으로 발전하지만, TAI 법령엔진이라는 공통 데이터 소스를 사용한다.

```
TAI Core (법령엔진) → 데이터 제공
TAI SaaS (운영)    → 진단 결과 운영
TAI MKT (마케팅)   → 고객 발견과 첫 관계
```

MKT가 없으면 고객이 TAI를 발견할 수 없다. Core가 없으면 MKT의 콘텐츠와 진단이 정확하지 않다. SaaS가 없으면 진단 이후 운영할 수 없다.

---

## 8. MKT 서비스 정의 (요약)

MKT는 TAI의 법령엔진 데이터를 기반으로, 고객이 자신의 안전 문제를 해결하는 과정에서 TAI를 발견하고 첫 관계를 시작하도록 만드는 마케팅 서비스이다.
