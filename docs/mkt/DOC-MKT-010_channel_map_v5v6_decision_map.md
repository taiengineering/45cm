## v5: Edge(관계) 정의

지도는 노드만 있어서는 안 된다. 반드시 길(Edge)이 있어야 한다.

### 관계 표준화

| 관계 | 의미 | 예시 |
|---|---|---|
| 포함한다 | 상위가 하위를 포함 | Google → 포함 → SEO |
| 연결된다 | 서로 다른 노드가 연결 | FAQ → 연결 → 무료진단 |
| 이동한다 | 사용자가 이동 | Google → 이동 → 홈페이지 |
| 공유한다 | 하나의 노드가 여러 채널에 존재 | FAQ → 공유 → Google, ChatGPT, 네이버 |
| 참조한다 | 한쪽이 다른쪽을 참조 | ChatGPT → 참조 → 국가법령정보센터 |

### 접점 = 팻말(Sign)

FAQ, 블로그, 영상, 체크리스트, PDF, 사례, 뉴스, 계산기, 질문, 답변은 전부 팻말이다. 접점이라는 이름보다 팻말이 더 적합하다.

### 지도가 단순해진다

```
채널 → 세부채널 → 팻말 → 목적지
```

목적지는 현재 하나: 무료진단.

```
Google → SEO → FAQ → 무료진단
ChatGPT → Search → 답변 → 무료진단
```

TAI가 관리해야 하는 핵심 자산은 팻말이다. 채널은 팻말을 놓는 장소일 뿐이다.

## v6: 교차로(Intersection) + 의사결정

### 지도의 4요소

```
길(Path) → 교차로(Intersection) → 팻말(Sign) → 목적지(Destination)
```

### 1. 길 (Path)

사람이 이동하는 통로: Google, ChatGPT, 네이버, YouTube, 카페

### 2. 교차로 (Intersection)

사람이 선택하는 순간.

```
Google 검색 → 검색결과 → ① 국가법령정보센터 ② KOSHA ③ 우리 사이트 ④ 경쟁사
```

```
ChatGPT → 답변 → ① 추가질문 ② 링크클릭 ③ 종료
```

### 3. 팻말 (Sign)

교차로에서 고객이 보는 것: FAQ, 블로그, 영상, 체크리스트, PDF, 사례, 뉴스, 계산기

### 4. 목적지 (Destination)

현재 하나: 무료진단

---

## 핵심 발견: 의사결정 지도

우리가 그리고 있는 것은 채널 지도가 아니라 고객의 의사결정 지도이다.

```
길 → 교차로 → 의사결정 → 팻말 → 목적지
```

예시:

```
Google → 검색결과 → "이게 나와 관련 있는가?" → FAQ → 무료진단
```

```
ChatGPT → 답변 → "신뢰할 수 있는가?" → 체크리스트 → 무료진단
```

중요한 것은 Google이 아니라 "클릭할까?"이다. ChatGPT가 아니라 "믿을까?"이다.

---

## 지도 완료 기준

채널 지도 작업의 완료 기준은 다음 네 가지가 모두 정의되는 것이다.

1. **길(Path)**: 고객이 이동하는 공간
2. **교차로(Intersection)**: 고객이 선택하는 지점
3. **팻말(Sign)**: 고객이 선택의 근거로 보는 정보
4. **목적지(Destination)**: 현재는 무료진단

이 네 요소가 정의되면, TAI는 채널 목록이 아니라 고객 이동 지도를 기반으로 팻말을 배치할 수 있는 지도를 갖게 된다.

지도 자체를 더 키우는 것이 아니라, 이 지도 위의 각 교차로에 어떤 팻말을 배치할지를 설계하는 작업이다. 이 시점부터는 지도 제작이 아니라 콘텐츠 전략의 영역이다.
