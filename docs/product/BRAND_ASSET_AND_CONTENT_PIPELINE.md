# Brand Asset & Content Pipeline Runtime

## 철학

```
좋은 콘텐츠는 매번 새로 만드는 것이 아니라,
브랜드 자산을 재활용/적응/진화시키는 것이다.
```

## Content Pipeline

```
Raw Idea → Asset Extraction → Hook Generation → Surface Adaptation
→ CTA Adaptation → Studio Preview → Approval → Publish
→ Performance Memory → Reuse
```

## Asset Types

| 유형 | 설명 | 예시 |
|------|------|------|
| hook | 3초 Hook, 첫 문장 | "산업재해 신고, 전화로?" |
| visual | 이미지/카드 | TAI 클린 카드 |
| cta | CTA 문구 | "무료 진단 신청" |
| content | 콘텐츠 원본 | FAQ 시리즈 |
| template | 템플릿 | 블로그 구조 |
| caption | 자막 | Shorts 자막 |

## Asset Lifecycle

```
new → active → stable → fatigued → archived → revivable
```

## Asset Scoring

요소: engagement(25%) + trust(25%) + reuse(15%) + (100-fatigue)(15%) + approval(20%)

등급: A(80+) / B(60+) / C(40+) / D

## Hook Library

| 유형 | 용도 |
|------|------|
| 3sec_hook | Shorts/Reels 첫 3초 |
| opening_sentence | 글 첫 문장 |
| title_pattern | 제목 패턴 |
| shorts_intro | 순동영상 도입 |
| authority_intro | 전문성 도입 |

## Shorts Pipeline

```
hook(3초) → problem(8초) → value(12초) → CTA soft(7초)
```

## Content DNA

브랜드 콘텐츠 특성: tone / energy / ctaDensity / authorityLevel / trustLevel / humor / eventIntensity

## Multi-Asset Adaptation

```
원본 → Blog (very_high) + LinkedIn (high) + Instagram (medium) + Shorts (very_low) + Kakao (low)
```

## Performance-linked Memory

어떤 자산이 실제로 효과적이었는가 추적
